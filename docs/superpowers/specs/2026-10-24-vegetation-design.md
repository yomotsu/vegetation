# vegetation — ランタイム植生メッシュ生成ライブラリ 設計

## 意図

terrain-gen / terrain-kit のような地形の上に、木・草・岩などを数千個散らすゲームフィールドを作りたい。
現状の植生は Blender で作った glTF + テクスチャのアセットで、LOD ごと・種類ごとにファイルが増える。

このライブラリは **植生オブジェクトをモデルファイルなしでランタイムに生成する** TS パッケージ。

- ファイル容量を節約する（モデル・テクスチャのアセットを配信しない）
- ローポリだが見栄えが良い
- 全種類で LOD0〜LOD4 を持つ
- three.js の Mesh としてそのまま使える

```ts
import { TreeMesh } from 'vegetation';

const tree = new TreeMesh( { seed: 3, leafColor: '#5a8f3a' } );
scene.add( tree );
```

## ゴール

1. 6 種類の植生を生成する: **grass / tree / flowers / bush / pebbles / rock**
2. 各種類に **LOD0〜LOD4** を用意する
   - LOD0 は参考アセット（terrain-gen `assets/vegetation/`）と同程度の精度
   - LOD4 はビルボード（板ポリ）
3. 生成結果は three.js の `Mesh`。`new TreeMesh()` のように使える
4. 花や葉の色などをユーザーが変えられる
5. **tree と rock はコライダ用ジオメトリも同時に生成する**。tree のコライダは幹のみ
6. インスタンス化（`InstancedMesh`）するかどうかはユーザーが決める。ただしインスタンス化して使うことが多い前提で、LOD ごとの geometry / material を単体で取り出せるようにする
7. **WebGLRenderer と WebGPURenderer の両方で動く**
8. three.js でプレビューできる **デモ HTML** を同梱する

## 非ゴール

- 地形上への配置・散布（ブルーノイズ配置、密度マップ、チャンクストリーミング等）。これは terrain-kit 側の責務
- 物理エンジンとの結合。コライダは `BufferGeometry` として返すだけで、meshwalk / rapier 等への登録は利用側
- 風（揺れ）のシェーダー。v1 では入れない（※Claude の判断。後から追加しやすいよう、揺れ用の重みを頂点属性に持たせるかは実装者判断）
- glTF 等へのエクスポート
- Ivy（参考アセットにはあるが今回の対象外）

## アンチゴール（技術的に動いてもこうなったら失敗）

- 生成に時間がかかりすぎて、数種類×数バリエーションの生成でページ起動が目に見えて止まる
- 同じ `seed` で毎回違う形になる（決定的でない）
- 片方のレンダラーでしか正しく表示されない
- LOD 間で色・シルエットが大きく変わり、切り替えがはっきり見える
- 色を変えるたびにジオメトリの再生成が必要になる

## 決まっていること

### 使い方の形

- 種類ごとにクラスを提供する: `GrassMesh` / `TreeMesh` / `FlowersMesh` / `BushMesh` / `PebblesMesh` / `RockMesh`
- 各クラスは `THREE.Mesh` を継承し、`new XxxMesh( options )` で即座に使える
- オプションで `seed` と `lod` を受け取る。同じ `seed` なら同じ形（決定的）
- 色はオプションで指定でき、生成後もマテリアル側で変更できる（ジオメトリ再生成不要）
- tree / rock はインスタンスに `collider: BufferGeometry` を持つ

### 見た目のスタイル

- **まずは stylized な見た目**で作る（参考アセットと同じ方向性）
- 将来、別スタイルとして**リアルな見た目を追加するかもしれない**。そのとき stylized を壊さずに追加できる構造にしておく（例: 形状生成とスタイル＝マテリアル・テクスチャ・頂点カラーの付け方を分離し、`style` オプションで切り替えられる余地を残す）。v1 でリアル系を実装する必要はない

### インスタンス時の LOD 切り替え

- **ユーザー（利用側）に任せる**。ライブラリは LOD ごとの geometry / parts を渡すだけで、InstancedMesh の LOD 振り分けやメモリ最適化の仕組みは提供しない
- 非インスタンス用途の `XxxMesh.createLOD()`（`THREE.LOD` を返す）は提供する

### バリエーション

- `seed` を変えると形が変わる。インスタンス化時は「種類ごとに数パターン生成して回転・拡縮で散らす」使い方を想定

### レンダラー

- WebGL と WebGPU 両対応のため、ライブラリは `three` からのみ import する（`three/webgpu` や TSL、`onBeforeCompile` は使わない）。**例外（2026-10-26）**: LOD4 のビルボード用マテリアルだけは独自シェーダー可（下記「制約」）。WebGPU 版は別エントリ `vegetation/webgpu` に置く
- マテリアルは標準の `MeshStandardMaterial` / `MeshLambertMaterial` 系に留める。WebGPURenderer は標準マテリアルを自動でノードマテリアルに変換して描画する。**変更（2026-10-25）**: Lambert は使わない。PartDef が `specularIntensity` / `ior` を持つ場合は `MeshPhysicalMaterial`（参考 glTF の葉と同じ低スペキュラ）
- terrain-kit は `three` → `three/webgpu` の alias を張っているので、その環境でも同じクラスが解決される

### デモ

- ブラウザで開いて以下ができる:
  - 種類を選んで表示
  - `seed`、色を変える
  - LOD0〜LOD4 を切り替えて見比べる（並べて表示も）
  - コライダの表示切り替え（ワイヤーフレーム）
  - 地面に大量に並べて（InstancedMesh）重さを確認する
  - WebGL / WebGPU の切り替え

### パッケージ構成

- TypeScript（strict）。ビルドは Vite ライブラリモード（ESM）+ `tsc` で型定義を出力
- `three` は peerDependency（`>=0.170`）。それ以外のランタイム依存はゼロ（乱数・ノイズは自前実装）
- テストは vitest。デモは Vite の dev サーバーで動く `demo/` ディレクトリ
- コードスタイルは参考プロジェクトと同じ mrdoob スタイル（タブ、`f( x )`、ブロック開始後の空行）。コメントは日本語

### API の詳細

```ts
// 1 つの LOD の Mesh
const tree = new TreeMesh( {
	seed: 3,
	lod: 0,            // 0〜4、既定 0
	leafColor: '#5a8f3a',
	barkColor: '#6b4a32',
} );
tree.collider;       // BufferGeometry（tree / rock のみ）

// LOD を自動で切り替えたい場合（THREE.LOD を返す。全 LOD でマテリアルを共有）
const treeLOD = TreeMesh.createLOD( { seed: 3 }, [ 0, 15, 30, 60, 120 ] );

// インスタンス化したい場合：geometry と material を単体で取り出す
const { geometries, material, collider } = generateTree( { seed: 3 } );
// geometries[ lod ] : BufferGeometry, material : Material | Material[]
const instanced = new THREE.InstancedMesh( geometries[ 2 ], material, 5000 );
```

- 複数マテリアル（例: 幹と葉）は 1 つの geometry の groups + マテリアル配列で表現する。これにより `Mesh` と `InstancedMesh` のどちらでも 1 オブジェクトで描ける
  - **変更（2026-10-25）**: three r186 の WebGPU で、groups を持つ複数マテリアルの Mesh の影描画が壊れる（影パスでバッファが破棄され描画失敗）。そのため `VegetationMesh` は「part ごとに単一マテリアルの子 Mesh」で描く（ルート = 最初の part、残りは子。castShadow / receiveShadow は子に伝播）。groups 付きの `geometries[ lod ]` も引き続き取り出せる
- 色の変更は `tree.setLeafColor( color )` のようなメソッド、または共有マテリアルの `color` を直接変更。参照共有している全インスタンスに反映される
- 原点は根元（地面との接地点）、+Y が上。単位はメートル

### 見た目の作り方

- **基本は頂点カラー + フラット寄りのシェーディング**（ローポリらしさとファイルゼロを両立）
- 葉・草・花びらのように輪郭が必要なものは、**ランタイムで生成する小さなテクスチャ**（`DataTexture`、アルファマスク）を貼ったカードを使ってよい。テクスチャは型付き配列で生成し、Canvas / DOM に依存しない（Node・Worker でも生成できる）
- テクスチャはグレースケール寄りで生成し、色はマテリアルの `color` で乗算する → 色変更が即反映
- 頂点カラーは明度・色相のゆらぎ（根元が暗い、先端が明るい等）に使う

### LOD の定義

| LOD | 内容 | 三角形数の目安（LOD0 比） |
|---|---|---|
| LOD0 | 参考アセット相当 | 100% |
| LOD1 | 細部を削減 | ~50% |
| LOD2 | 主要形状のみ | ~25% |
| LOD3 | シルエットがわかる最小限（例: 木なら幹 + 葉の塊数個） | ~10% |
| LOD4 | ビルボード。交差した 2〜3 枚の板ポリ（4〜12 tris） | – |

- LOD4 のテクスチャは **LOD0 の形状を CPU で正射影ラスタライズ** して生成する（レンダラーに依存しない、同期で生成できる）。正面・側面のシルエットと簡易ライティングを焼き込む
- LOD1〜3 は LOD0 を間引くのではなく、同じ seed から粗いパラメータで生成し直してよい（シルエットと色が揃っていれば手段は問わない）
- **確定（2026-10-26〜27、ユーザー決定）**: 上の表の LOD3 / LOD4 は次のように変わった
  - tree LOD3: 幹と葉を焼き込んだ **6 枚の板の交差**（30° 刻み、6 方向の絵をアトラスに焼く）＋真上から見た水平の板 1 枚
  - rock / pebbles LOD3: 板ではなく **超ローポリの実メッシュ**（頂点カラーは LOD0 の平均色）
  - LOD4（全種類）: **常にカメラを向く縦の板 1 枚**（Y 軸固定の円筒ビルボード）＋**真上用の水平の板 1 枚**。水平の板の高さは「上から 75% = 地面から 25%」。見下ろし角に応じてディザでクロスフェード（SpeedTree 方式）
  - InstancedMesh 用に、インスタンスをカメラに向ける CPU ヘルパー `orientBillboardInstances` を提供

### 種類ごとの形

- **tree**: **terrain-gen `assets/vegetation/Tree01_LOD0.gltf` に近い針葉樹**（2026-10-24 ユーザー決定。当初の広葉樹は置き換え）。まっすぐな 1 本の幹（木目テクスチャ）に、水平〜やや垂れた枝葉カード（針葉の枝を描いたテクスチャ、アルファマスク）が段（輪生）状に付き、上ほど短い円錐形のシルエット。葉の法線はほぼ上向き（Tree01 と同じ stylized な陰影）。テクスチャはすべてランタイム生成
- **bush**: **（2026-10-26 ユーザー決定: 今回は対象外・保留）** 地面から複数の短い枝、葉カードのクラスタ。tree の生成ロジックを共有してよい
- **grass**: ~~1 株に複数の刃。刃は先細りの細長いポリゴン、根元暗・先端明の頂点カラー~~ → 2026-10-29 確定: 刃を描いたカード 1 枚（下記「実装で確定したこと」）
- **flowers**: 茎＋花びら＋花芯。1 メッシュに数本。`petalColor` / `centerColor` / `stemColor` を指定可（2026-10-29 確定: allium / daisy。下記「実装で確定したこと」）
- **pebbles**: 小さなローポリ石を数個〜十数個まとめた 1 メッシュ。コライダなし（2026-10-27: 丸みのある川石。粒は参考 Pebbles01 と同じかそれより小さく）
- **rock**: ~~ノイズで変形した低分割球体（フラットシェーディング）~~ → 2026-10-27 確定: 不規則な多面体（下記「実装で確定したこと」）。苔は `moss` オプションで追加予定

### コライダ

- `BufferGeometry`（位置 + インデックスのみ）で返す。メッシュと同じローカル座標系
- tree: 幹のみの低分割角柱（8 角程度、30 tris 前後）。枝・葉は含めない
- rock: LOD2 相当の低ポリ（~100 tris 以下、閉じた形。メッシュの底は開いていてもコライダは閉じる）。~~凸包にはしない（凹みを残す）~~ → 形そのものが凸包ベースになったため、コライダも凸包ベース（たまに付く大きな凹みは含む）

### レビュー後に Claude が決めたこと

- **出力の形は 2 通り**:
  - `XxxMesh` は 1 つの geometry + groups + マテリアル配列（`Mesh` として 1 オブジェクトで描ける）
  - `generateXxx()` は LOD ごとに **parts 配列**（`{ geometry, material }[]`、マテリアル 1 つにつき 1 part）も返す。terrain-kit の `partsFromScene` のように「part ごとに InstancedMesh を 1 つ作る」パイプラインにそのまま流せる
  - 両者は同じマテリアルインスタンスを共有する
- **マテリアルは `MeshStandardMaterial` のみ**にする。Lambert は WebGPU 側の変換で unlit になる事例があるため使わない
- **色変更の範囲**: 利用側がマテリアルを clone した場合（例: terrain-kit の `toNodeMaterial`）、その複製には色変更が届かない。これは利用側の責務とし、README に明記する
- **LOD4 の色**: ビルボードのテクスチャには複数パーツ（葉と幹、花びらと茎など）の色とライティングを焼き込む。色を変えたときは**テクスチャだけ焼き直す**（ジオメトリは再生成しない。焼き直しは数 ms 程度に収める）。LOD3→LOD4 の切り替えで色が飛ばないよう、焼き込みは現在のマテリアル色を使う
- **WebGL の意味**: three の従来の `WebGLRenderer` と `WebGPURenderer`（WebGPU バックエンド）の両方。ライブラリは `three` のみ import するので、どちらの環境でも動く。デモは 1 ページに 2 つの three を読み込まないよう、起動コマンドを分ける（`npm run demo` = WebGL、`npm run demo:webgpu` = `three` → `three/webgpu` alias で WebGPU）
- **Worker 対応の層を最初から分ける**:
  - 内部は 2 層構造にする
    - `core/`: 純データ層。型付き配列だけを扱い、`three` に依存しない。Worker で実行でき、結果を transfer できる
    - `three/`: 上の層。core の結果を `BufferGeometry` / `Material` / `Mesh` に包む
  - Worker そのものはライブラリに含めない
- **風**: v1 では実装しない。ただし将来のため、`windWeight` 頂点属性（0 = 根元・固定、1 = 先端・最大の揺れ）を全 LOD に入れておく（terrain-kit の既存の属性名に合わせる）

## 実装者に任せること

- 乱数（mulberry32 等）・ノイズ（simplex / value noise）の具体的な実装
- 木の分岐アルゴリズムの詳細（space colonization / L-system / 単純再帰など）
- 生成テクスチャの解像度（目安 64〜256px）
- 各オプションの既定値と細かいパラメータ名
- デモの UI ライブラリ（lil-gui 等）とレイアウト
- 生成をキャッシュするか（同じ seed × オプションでジオメトリ共有）

## 制約

- **LOD4 の板（2026-10-26 ユーザー決定）**: SpeedTree 方式。縦のビルボード（横から見た絵）と水平の板（真上から見た絵）を、カメラの見下ろし角に応じてシェーダーでディザ・フェードして切り替える。このマテリアルに限り独自シェーダーを許可（WebGL は onBeforeCompile、WebGPU は `vegetation/webgpu` エントリで TSL 版を登録）

- **頂点数（2026-10-25 ユーザー決定）**: tree の各 LOD の頂点数は参考 Tree01 と同じかそれ以下（LOD0 ≤ 795、LOD1 ≤ 513、LOD2 ≤ 331）。少ないほど良いが、見た目は参考を保つこと

- 参考プロジェクトの教訓（terrain-kit `CLAUDE.md`）:
  - WebGPU で `count = 0` の可視 InstancedMesh はクラッシュする（デモで注意）
  - 量子化属性に `applyMatrix4` すると ±1 にクランプされる → 生成ジオメトリは Float32 のままにする
- 数種類 × 数 seed × 5 LOD を生成しても、ページ起動を体感で止めない程度の速さ（目安: 1 種類 1 seed の全 LOD 生成が数十 ms 以内）

### 内部構成

- `src/core`: three に依存しない純データ層（型付き配列。MeshData、PartDef、VegetationData、TextureData）
  - TextureData は「行 0 = v=0（下端）」で、`flipY = false` でアップロードする
- `src/three`: VegetationAsset / VegetationMesh / meshes.ts（TreeMesh、RockMesh、PebblesMesh）
- `src/webgpu`: LOD4 クロスフェードの TSL 版（`vegetation/webgpu` エントリ）
- 色の変更:
  - 葉はテクスチャを作り直す（登録制の再生成）
  - 樹皮と岩は「グレースケールのテクスチャ × マテリアルの色」の乗算
  - 樹皮の既定色は `0x6b4c32`

### tree（2026-10-26 ユーザー承認）

- 参考 Tree01 に近い針葉樹
  - 枝葉は 3×3 分割のカードで、V 字に折れて上に反る。法線は +Y 寄り。上の段ほど立ち、小さくなる
  - 頂上は枝葉で隠し、幹の先端も閉じる
- 葉のテクスチャ（モミの小枝）はランタイム生成
  - 輪郭はアンチエイリアス済みのアルファ
  - v=0 側が付け根。中心の茎は幹と同じ色で、付け根が太く、先端の手前で終わる
  - 針葉は先端へ向かうほど枝の方向にそろう
- 色合わせは描画結果の実測で行う
  - `leafBrightnessStops` を調整した
  - 葉は `MeshPhysicalMaterial`（`specularIntensity` 0.014872、`ior` 1.05）。参考 glTF と同じ設定
- 既定値
  - `height` 7.5
  - `branchCount` 10
  - `leafColor` 0x2f7d1f。デモにプリセット（緑 / 紅葉の赤 / オレンジ / 黄）あり
  - 幹を地面の下へ 0.3 ×（樹高 / 7.55）m 伸ばす（斜面用）。コライダも伸ばす。オプションにはせず固定（2026-10-29 ユーザー決定）
- 頂点数の上限: LOD0 ≤ 795、LOD1 ≤ 513、LOD2 ≤ 331。現在は 516 / 209 / 140 / 28 / 8 頂点
- LOD1 / 2 は段ごとの 5 枚の枝葉を 1 枚のお椀（扇形）にまとめる（2026-10-29 ユーザー採用）
  - テクスチャ `leafRing`: 各段の LOD0 の枝葉を真上から焼いたアトラス（1 段 128px の横一列、既定 1280×128）。UV は水平位置そのままなので LOD1 / 2 で共有できる
  - 焼くときは不透明な面同士だけで高さを比べる。透明な隙間が下の葉を消すと、付け根が空いて幹から浮いて見える
  - 縁は 10 頂点（枝葉の向き 5 + その間 5）。間の頂点を枝葉の幅 × `lodFrondFoldRatio` × 3.5 だけ持ち上げ、V 字の折れの代わりに横からの厚みを出す。この倍率は真横からの葉の量が LOD0 の 70% 以上になるように選んだ
  - LOD2: 中心 + 縁 10 = 1 段 11 頂点・10 三角形。LOD1: 中心 + t=0.4 の 5 点 + 縁 10 = 16 頂点・20 三角形
  - 頂上の 1 枚（leader）は従来どおり `leaf` パートのカード。LOD1 / 2 はパートが 1 つ増える（draw call +1）
  - 葉の色を変えると `leafRing` も焼き直す（`tree-leaf-ring` 生成器）
  - 真上から見ると LOD0 より葉が 15〜20% 少ない（128px に焼くため細い針葉が欠ける）
- LOD3 / 4 のインポスターは視線角度によるディザの切り替えをせず、縦・上面のカードを常に描く（2026-10-29 ユーザー採用。rock / pebbles も同様。切り替えが残るのは flowers のみ）
  - パートの `impostorFade: false` で指定する
  - カメラを向く LOD4 の縦カードは、影を描くときだけ光源へ向ける。視点カメラの向きのままだと、オービットに合わせて影の幅と位置が変わる
- LOD0 へのお椀の適用は試して不採用（2026-10-29 ユーザー決定）
  - 516 → 276 頂点になるが、近くで見るには 1 段 512px が必要で、アトラスが木 1 種あたり約 12MB、生成が約 166ms になる
  - 段が厚いスカート状になり、枝葉ごとの区切りと中央の明るさが失われる

### rock（2026-10-27 時点。ユーザー評価「とても良い」）

- 形: 楕円体の表面にばらつかせた点群の **凸包 = 不規則な多面体**
  - ときどき大きな凹み（scoop）を付ける
  - 鋭すぎる角は出さない（頂点の錐角・二面角・三角形の最小角をテストで保証）
  - `weathering`（既定 0.25）で角の削れ具合を調整する
- 埋まり方: 全体高の約 0.39〜0.45 を地中に沈める（`burial`）。メッシュの底は穴が開いていてよく、コライダは閉じる
- LOD0 の面取り: 多面体の各面を内側にずらし、辺には帯、頂点には角パッチを張る
- LOD0 の法線（2026-10-28 修正）: **面単位の重み付け法線**にする
  - 平らな面の頂点は、その面の法線をそのまま持つ
  - 面取りの帯と角パッチは、隣り合う面の法線の間を補間するだけにする
  - 以前の折り目付き平滑法線（35°）は帯の法線が面の頂点に混ざり、大きな三角形の上に明暗の三角形・ギザギザが出た
  - 三角形の向きは、意図した法線に合わせて 1 枚ずつそろえる。角パッチだけは隣と矛盾しない向きにする
- 色: アルベドは明るいグレーにする
  - 暗さはテクスチャに入れず、シェーディングで出す
  - 主要な稜線だけ、テクスチャで柔らかく明るくする
  - 細く先細りで枝分かれするひび割れの溝を 2〜4 本入れる
  - テクスチャは 1024²（seed ごとにキャッシュ）
  - pebbles と共通の石テクスチャ
- LOD0 頂点数: 上限 260（seed 1〜5 で 137〜165 程度）
- seed は内部で salt をかけている（既定の seed 1 が見栄えの良い形になるように）
- LOD の構成（2026-10-28 ユーザー指定）
  - LOD1: 地上の大きな面だけを中心分割し、頂点数を LOD0（重複削除後）の約半分（45〜55%）にする
  - LOD2: 凸包の点を貪欲に間引いた約 22 三角形
  - LOD3: さらに間引いた約 16 三角形。15 以下では真上・真横の輪郭一致（IoU ≥ 0.75）を守れない
  - seed 1 の例: 205 / 116、50 / 59、22 / 42、16 / 36、4 / 8（三角形 / 頂点）
- UV: LOD1〜3 も LOD0 と同じ球面投影の中心と U オフセットを使う。ひびの位置を全 LOD でそろえるため
- 重複頂点: 位置・法線・UV・色などの全属性がビット単位で一致する頂点だけを最後にまとめる
  - LOD0 が 8〜25% 減る
  - 折り目の分割とテクスチャ継ぎ目の複製は残す
- LOD3 の陰影は 35° の折り目分割のままにする（2026-10-28 ユーザー決定）
  - 平滑法線（約 13 頂点）と 60° 分割（約 25 頂点）を同じカメラで比較した
  - どちらも LOD0 / LOD2 と明暗の付き方がずれるため却下した
- `closeBottom`（既定 false）
  - true のときは、地中側も簡略化せず完成した形にする
    - 下側の稜線点、地中の大きな面の分割、底面を残す
    - LOD の間引きも全周で評価する
  - 全 LOD が閉じたメッシュになる
  - false の出力は以前とバイト単位で同じ

### poppy / bluebell / calla / primrose（2026-10-29 ユーザー採用）

- 参考: Sketchfab「Stylized Low Poly Flowers Pack 01 / Vol-8」のサムネイル（`.superpowers/sdd/2026-10-24-vegetation/flowers-ref/`）。どの花も地際に葉を広げる
- 5 種を試作し、cushion（花のクッション）は廃棄。コードは種類ごとに `src/core/flowers/<名前>.ts`
- 共通の決まり（試作で見つかった不具合から）
  - 交差させた茎カードは同じ段数・同じ曲線に沿わせる。直線の茎を重ねない
  - 花・つぼみ・釣り鐘は、実際に描かれる茎（段のあいだは直線）の先・上に付ける。曲線上の点に付けると、茎から浮いたりはみ出したりする
  - 葉の UV は葉の絵の位置から求め、絵の根元を茎の根元に合わせる。ひし形のカードは絵の幅の 2 倍に広げ、絵が縁で切れないようにする。葉の絵はテクスチャ内で縦 1 列に並べ、隣の葉を拾わないようにする
  - 位置と属性がまったく同じ頂点は LOD0〜2 で 1 つにまとめる（`weldIdenticalVertices`）。まっすぐなカードは 1 段にする

- calla: 実物のオランダカイウに合わせる。苞は筒から上へ広がるラッパ形で、背の先は尖って後ろへ反り、前の口は外へ反る。黄色い肉穂。葉は葉柄なしで根元から直接立ち上がり、中ほどで最も広く先が尖る。左右の縁を茎の側へ寄せて茎を包むように丸める。花の長さ 11 cm、葉の長さ約 27 cm・幅約 10 cm
- primrose: 地面に張り付く葉のロゼット。花房は中心を下げたお椀形（LOD0 のみ）で、傾きは約 24°。茎のテクスチャは根元の 1 本から 5 本の花柄が扇形に分かれ、花房の縁まで届く
- LOD0 の頂点数（既定の株数）: poppy 126 / bluebell 144 / calla 132 / primrose 148

### デモの草原（2026-10-29 ユーザー承認）

- 草の scatter は専用の処理（`demo/grassScatter.ts`）。密度と距離の処理は terrain-gen の値に合わせる
  - 0.11 m の格子のセルを 15% の確率で残す（約 12 枚/m²）。間引きは青色雑音で、ばらけて均一にする
  - 高さ 0.3〜0.6 m、幅は高さ × 1.125、向きはランダム、明るさ ±6%（色相は変えない）、根元を 0.03 m 沈める
  - 描画範囲 48 m。12〜40 m で丈を 10% まで縮め、24〜40 m で 45% まで間引き、40〜48 m で消す
- 草の scatter のときだけ、地面を草の色 × 0.75 にし、ライトを 0.62 倍にする
  - terrain-gen は地形も緑なので、カードの隙間が目立たない。それに合わせる
  - 草は法線が上向きなので、デモの明るいライトでは白っぽく見える
  - 値はブラウザで walkthrough と見比べて決めた
- `camera reset` は、草の scatter のときだけ目の高さ 1.7 m から前を見る（walkthrough と同じ）
